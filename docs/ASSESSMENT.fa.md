# زمان‌بندی و ارزیابی

هر روز یک integration کوتاه داشته باشید. کارها را بر اساس interface تقسیم کنید تا داده، مدل، API و انتشار هم‌زمان پیش بروند. مشکل زیرساخت مشترک را زود به تیم آموزشی اطلاع بدهید؛ منتظر روز نمایش نمانید.

| روز | خروجی قابل بررسی |
|---|---|
| ۱ | تقسیم مسئولیت، قراردادها، دریافت batch، schema و تست ورودی؛ اسکلت API و pipeline |
| ۲ | ingestion تراکنشی و idempotent؛ feature مشترک؛ baseline و تقسیم زمانی |
| ۳ | دو مدل و ارزیابی، ثبت MLflow، DAG ingestion و ارسال Job آموزش |
| ۴ | API احراز هویت‌شده، batch priority، تست قرارداد و image قابل اجرا |
| ۵ | staging، Helm، probe و منابع، CI؛ مسیر تأیید دستی production |
| ۶ | dashboard و هشدارها، تست بار، نمایش مستقل HPA و بررسی ظرفیت |
| ۷ | اجرای replay گروه روی بازهٔ بعدی داده، ثبت پیش‌بینی و ارزیابی پس از زمان دسترسی برچسب |
| ۸ | پایش، پیشنهاد retraining، مقایسهٔ candidate/champion و تصمیم انتشار مستند |
| ۹ | رخداد در بازهٔ اعلام‌شده، بازیابی و rollback، تکمیل runbook |
| ۱۰ | نمایش سناریوی کامل، تحویل شواهد و دفاع فردی |

نمرهٔ گروه از ۱۰۰ محاسبه می‌شود:

| بخش | امتیاز | شواهد اصلی |
|---|---:|---|
| داده و کیفیت | ۱۵ | روابط درست، تراکنش، receipt، retry، قرنطینه، cutoff |
| مدل و ارزیابی | ۱۵ | دو رویکرد، baseline، نبود leakage، معیار کسب‌وکار، calibration |
| orchestration و lifecycle | ۱۵ | DAG واقعی، retry، Job صف‌دار، lineage و MLflow |
| API و تست | ۱۰ | قرارداد، feature parity، احراز هویت، خطا و retry |
| Kubernetes و CI | ۲۰ | Helm، probe، replica، منابع، HPA، staging، تأیید دستی و rollback |
| پایش و retraining | ۱۵ | dashboard، فعال شدن و رفع هشدار در Grafana، drift، بلوغ برچسب، علت آموزش و gate؛ ارسال اعلان خارجی الزامی نیست |
| رخداد و تحویل | ۱۰ | تشخیص، بازیابی قابل تکرار، runbook، محدودیت‌ها و شواهد |

نمرهٔ فردی از ۱۰۰ است: ۴۰ امتیاز مشارکت قابل بررسی در commit/MR/review، ۴۰ امتیاز دفاع و تشخیص یک مسئله، ۲۰ امتیاز توضیح یک تصمیم در بخشی غیر از مسئولیت اصلی. فرمول نهایی: `۰٫۸ × نمرهٔ گروه + ۰٫۲ × نمرهٔ فردی`. تعداد commit یا تعداد خطوط کد به‌تنهایی معیار مشارکت نیست.

معیار ارزیابی، رفتار اجراشده و شواهد قابل بازتولید است. screenshot بدون نسخه، فرمان و زمان کافی نیست. برای هر آزمایش مهم commit، image digest، نسخهٔ مدل، cohort، فرمان، زمان و نتیجه را ذخیره کنید. یک index در `reports/evidence.md` قرار بدهید. secret را حذف کنید.

برخی نقص‌ها بخش مربوط به خودشان را نامعتبر می‌کنند: استفاده از برچسب آینده برای train، محاسبهٔ اشتباه target، خطای join که اعداد را چند برابر کند، نبود gate و تأیید دستی، یا نتیجه‌ای که روی محیط واقعی قابل اجرا نیست. تیم آموزشی علت و بخش متاثر را مشخص می‌کند. نصب و خرابی سرویس پایه که خارج از اختیار گروه باشد، به‌عنوان خطای پیاده‌سازی دانشجو ارزیابی نمی‌شود.

بازهٔ تمرین رخداد روز ۹ و نمایش روز ۱۰ از قبل اعلام می‌شود. دسته‌های عمومی رخداد: تکرار/قطع ingestion، schema خراب، drift و تأخیر label، candidate ضعیف‌تر، انتشار با readiness خراب، حذف pod، قطع MLflow و بازگشت نسخه. نمونهٔ دقیق برای هر گروه ممکن است متفاوت باشد. هدف، تشخیص و بازیابی همراه با توضیح است.
